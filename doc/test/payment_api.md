---
description: 測試案例規格 - 第三方金流與防偽驗簽 (payment_api)
---

> 狀態：初始為 [ ]、完成為 [x]
> 注意：狀態只能在測試全數通過驗收後由流程更新。
> 測試類型：金額防偽、金流渠道、參數校驗、簽章授權、訂單流轉、冪等防護

---

## [x] 【金額防偽】測試伺服器端防偽重算：若前端試圖竄改金額，伺服器必須強制依據官方定價重算
**範例輸入**：前端傳入帶有惡意價格 10 元的禮盒商品結帳請求
**期待輸出**：伺服器忽略前端價格，強制依官方定價計算，回傳 201 且 amount 為 3690。

---

## [x] 【金流渠道】測試唯一定錨 LINE Pay：拒絕非 linepay 之渠道（包含已封存之 ecpay）
**範例輸入**：結帳請求指定 provider 為 "ecpay"
**期待輸出**：回傳 HTTP 400 與 UNSUPPORTED_PROVIDER 錯誤碼。

---

## [x] 【參數校驗】測試非法商品數量（0、負數、超過 99）被伺服器阻斷
**範例輸入**：商品數量為 0 或負數
**期待輸出**：回傳 HTTP 400 提示數量必須介於 1 至 99 之間。

---

## [x] 【參數校驗】測試不存在於資料庫之惡意商品被精準阻斷
**範例輸入**：品項 ID 為 FAKE-ITEM-999
**期待輸出**：回傳 HTTP 400 提示找不到指定的官方商品。

---

## [x] 【參數校驗】測試顧客資料校驗：姓名為空或未留聯絡資訊時阻斷
**範例輸入**：顧客姓名為空字串或未提供 email/phone
**期待輸出**：回傳 HTTP 400。

---

## [x] 【簽章授權】測試 LINE Pay v3 HMAC-SHA256 標頭授權簽章產生器
**範例輸入**：URI、請求 body、Channel Secret 與 Nonce
**期待輸出**：產出合法之 Base64 HMAC-SHA256 簽名。

---

## [x] 【訂單流轉】測試建立 LINE Pay 測試沙盒訂單與支付跳轉參數
**範例輸入**：合法品項與顧客資訊，指定 provider 為 "linepay"
**期待輸出**：建立訂單成功，狀態為 PENDING_PAYMENT，回傳 paymentUrl。

---

## [x] 【訂單流轉】測試 LINE Pay Confirm API 完成扣款與狀態機轉移
**範例輸入**：由 sandbox 建立訂單後，調用 Confirm API 傳入 transactionId
**期待輸出**：訂單狀態轉移為 PAID，扣款成功。

---

## [x] 【冪等防護】測試 LINE Pay 扣款確認重複通知之冪等性防護
**範例輸入**：已完成付款的訂單再次收到 Confirm 通知
**期待輸出**：回傳已付款成功，不重複扣款且不報錯。
